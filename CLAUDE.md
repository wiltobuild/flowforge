## Meta-workflow (how this project's own build is managed)

Generated by `/bootstrap-project` on 2026-08-23. This is about the process of building the
site — separate from `AGENTS.md`, which is the contract for what gets built.

- [`docs/agent/project-profile.md`](docs/agent/project-profile.md) — identity, repository
  facts, constraints, role ownership, approval gates. Re-run bootstrap to refresh; don't
  hand-edit the Repository Facts section.
- [`docs/agent/workflow.md`](docs/agent/workflow.md) — GUIDE/COORDINATE/EXECUTE modes, the
  standard workflow per task type, Codex handoff, git strategy
- [`docs/agent/decisions.md`](docs/agent/decisions.md) — append-only log of approved
  decisions, so they aren't re-litigated in a later session
- [`docs/agent/roles/`](docs/agent/roles/) — Argus (investigate), Athena (plan), Themis
  (review), Apollo (verify). Prompt templates handed to the Agent tool, not registered
  subagent types.
- [`docs/tasks/`](docs/tasks/) — per-task artifacts (investigation, plan, handoff, review,
  verification) for M1 onward, per the Standard documentation tier

Recurring feature/fix work should go through `/start-task`, which reads this scaffold.

## Agent profiles

Reusable subagents are defined in [`.claude/agents/`](.claude/agents/). Use them rather
than re-deriving the same instructions:

| Agent | Use it when |
|---|---|
| `page-drafter` | Drafting a new content page from its type template |
| `content-auditor` | Checking frontmatter, tag validity, and template conformance |
| `data-verifier` | Re-verifying plan/model facts against provider sources |
| `field-report-triager` | Turning submitted usage reports into calibration data |

These files are dual-purpose: they are working build tooling **and** published site
content under `/agents/profiles/`. Keep them well-written and well-commented — people will
read them as examples of how to write an agent profile.

## Notes for Claude specifically

- Prefer editing existing content files over creating new ones. The content set is
  deliberately bounded by the collection schemas.
- When adding a fact about Claude plans, models, or Claude Code, apply the same neutrality
  standard used for every other vendor. This site is tool-agnostic in `/concepts` and
  honest in `/plans`. Do not soften the tradeoffs.
- Do not fetch live pricing during a build. Pricing is human-verified — see
  `AGENTS.md` → "Explicitly out of scope."
